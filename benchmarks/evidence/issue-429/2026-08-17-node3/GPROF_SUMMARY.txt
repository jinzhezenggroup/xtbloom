Issue #429 diagnostic gprof attribution
=======================================

Purpose
-------

This is a coarse sampling diagnostic used only to confirm that the selected
Mulliken leaf callbacks are reached by public CPU inference. It is not the
retained latency claim; RESULTS.csv and DISTRIBUTIONS.csv contain the
correctness-qualified Release timing evidence.

gprof -b build/issue429-gprof/xtbloom_cpu_public_inference_test gmon.out

Selected flat-profile observations
----------------------------------

Each sampling tick represented 0.01 seconds. The complete public inference
test accumulated 0.23 sampled seconds in forced-baseline mode and 0.14 sampled
seconds in forced-AVX2 mode. The coarse baseline flat profile directly sampled
both selected leaves:

  self_s  calls  function
     0.01   5315  mulliken_hamiltonian_chunk_baseline(void*, unsigned long)
     0.01   3580  mulliken_population_chunk_baseline(void*, unsigned long)

The forced-AVX2 call graph recorded the corresponding specialized leaves with
5464 and 3662 calls. Neither accumulated a complete 0.01-second sampling tick:

  self_s  calls  function
     0.00   5464  mulliken_hamiltonian_chunk_avx2_fma(void*, unsigned long)
     0.00   3662  mulliken_population_chunk_avx2_fma(void*, unsigned long)

Interpretation and limitation
-----------------------------

The forced-mode call counts confirm that public inference reaches the exact
leaf pair whose translation unit changes ISA. The lower complete-process
sample total and absence of a full tick in either AVX2 leaf are directionally
consistent with the Release timings, but gprof's 0.01-second granularity and
worker-thread attribution make this diagnostic unsuitable for quantifying the
speedup. Linux hardware-PMU profiling remained unavailable because
perf_event_paranoid=4.
